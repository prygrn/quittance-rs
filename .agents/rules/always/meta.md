# Meta: the rule standard

These rules define what a valid rule is. They apply to themselves.

- A rule is one sentence.
- A rule is unambiguous.
- A rule is verifiable.
- A rule contains no "but" and no "except when"; if it needs one, it is two rules.
- A rule is written in English.
- A kernel rule holds true for every project and every stack.
- A rule earns its brevity from atomicity, not from dropped words.
- A rule that only holds for one project, stack, or domain belongs in a module, not here.
- A rule that describes a single role's behavior belongs in a role skill, not here.
